# Tipdash accessibility & performance audit — 2026-10-10

**Scope:** Main dashboard (`index.html`) at **390×844** (2× DPR) and **1280×800** desktop, default **Apex** theme with a mocked TipBot session and one listed server on the home overview.

**Method:** Static review of HTML/CSS/JS, existing `tests/phone_a11y.test.js` guards, WCAG contrast math on design tokens, and headless Chrome (local static server + intercepted TipBot JSON). Metrics are **lab values** on a fast VM; production adds TLS, Render cold starts, and live API latency.

---

## Executive summary

Tipdash has invested heavily in phone-first patterns (44px targets on primary chrome, skip link, focus-visible rings, `prefers-reduced-motion` / `prefers-contrast` hooks, collapsible section semantics). The largest risks are **payload size** (monolithic `index.html` plus sixteen eager asset scripts before boot), **secondary controls** under the 44×44px guidance (home logo, promo dismiss, leg-chip remove, inline grade buttons), and **keyboard/focus ergonomics** on desktop Apex (left rail tab order precedes the sticky header; settings menu is not a focus trap).

## Priority findings

### P0 — Performance & first load

| ID | Finding | Suggested fix | References |
|----|---------|---------------|------------|
| P0-1 | **Very large initial document.** `index.html` is ~472 KB raw (~127 KB gzip). It embeds ~85 KB of CSS and ~378 KB of inline JavaScript (~127 KB gzip) in addition to external scripts. | Continue splitting the main script (builder/admin already lazy). Defer non-critical modules until first navigation (e.g. stats charts, compare, ESPN helpers). | P0-3 | **Parse/compile cost dominates cold start.** Even with fast local FCP (~48–56 ms), total JS decode+parse for inline+external approaches **~580 KB** before user interaction. ### P1 — Focus order & keyboard

| ID | Finding | Suggested fix | References |
|----|---------|---------------|------------|
| P1-8 | **Desktop Apex: left rail is inserted as the first child of `#app`**, so tab order visits all rail items before the sticky header (logo, gear) and main content. ### P2 — Screen readers & semantics

| ID | Finding | Suggested fix | References |
|----|---------|---------------|------------|
| P2-1 | **Duplicate “Settings” in name computation on desktop** — Apex rail includes a Settings nav button (`aria-label` from `NAV`) and the gear also exposes “Settings”. | Hide gear from accessibility tree when rail is visible (`aria-hidden="true"` on gear @min-width 900px) or rename rail entry (“Preferences”). | `assets/theme-apex.js` 676–679; `index.html` 1200 |
| P2-2 | **Toggle switches** (`button.toggle`) pair `aria-label` with a visible `<span>` label; some instances use `aria-pressed` instead of `role="switch"` / `aria-checked` (inconsistent state model). | Standardise on `role="switch"` + `aria-checked` (already used for feature-grade toggles at 4967). | `index.html` 4967, 6869 |
| P2-3 | **Calendar day cells** expose rich `title` tooltips but no `aria-label`; screen readers hear only day number and P/L value. | Add `aria-label` summarising the `title` string when rendering `cal-day` buttons. | `index.html` 6044–6047 |
| P2-4 | **Loading top bar (`#tb-loadbar`)** is `pointer-events:none` (good) but not exposed as progress; only the full-screen load panel has `role="progressbar"`. | Optionally set `aria-hidden="true"` on the decorative bar or tie it to the same live region as `TopBar`. | `index.html` 71–76, 1192 |

## What is working well

- **Skip link** to `#app` with visible focus (`index.html` 150–151, 1175).
- **Focus-visible** outlines on interactive elements (`index.html` 663).
- **Phone settings drawer** fixed to viewport with safe-area insets (`index.html` 1154–1170; covered by `tests/settings_drawer.test.js`).
- **Primary chrome** at 44px: gear, tabs, buttons, batch clear, top nav links (`index.html` 160–163, 1013; `tests/phone_a11y.test.js`).
- **Apex phone tab bar** — Build control 58×58 px, centred column (`assets/theme-apex.css` 571–598; `tests/tabbar_order.test.js`).
- **Collapsible panels** use `role="button"`, `aria-expanded`, keyboard handler (`index.html` 5927–5994, 6056).
- **Theme tokens on Apex** meet contrast for body/meta text (`index.html` 561–567).
- **Reduced motion** preserves opacity/colour feedback (`index.html` 702–706; `tests/apple_design.test.js`).

## Suggested remediation order

1. P0-1 / P0-2 — Reduce critical JS bytes and defer non-boot modules.
2. P1-1 / P1-4 — Fix undersized tap targets on home logo and grade rows.
3. P1-8 / P1-9 — Desktop focus order and settings menu trap.
4. P1-6 — Unify faint colour tokens on legacy themes.
5. P2-3 / P1-10 — Calendar and gear menu keyboard/ARIA polish.
